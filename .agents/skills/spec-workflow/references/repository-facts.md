# Repository facts: `spec-workflow`

Product-specific facts only. The common rules are in [SKILL.md](../SKILL.md). A repository's own `AGENTS.md` and `Specs/` win on any conflict. Paths are relative to that repository's root unless linked.

| Repository | Fact | Where it is defined | Kept because |
| --- | --- | --- | --- |
| `DxUi` | Read [Specs/README.md](../../../../../DxUi/Specs/README.md) and [AGENTS.md](../../../../../DxUi/AGENTS.md). Implemented support is recorded in `capabilities.json`; library tests do not replace consumer product qualification or deferred native-platform, IME and assistive-technology coverage. | `Specs/README.md`, `capabilities.json` | The `DxUi` library has consumers; the support record exists only there and in `RedTilde` and `RedMonitor`. |
| `DxUi` | Deferred consumer or platform scope stays on `HOLD`; close a plan only when implementation, tests and normative updates are complete. Add new in-scope work to `RemainingWork_*.md`. Validate links and indexes. | `Specs/README.md` | Consumers of the library depend on that deferral staying explicit. |
| `DxUi` | Validate changed guidance with `validate-skills.ps1` and `validate-specs.ps1`. For source or build work run the affected `test.ps1` configurations and the additional validation named by the contract. | `AGENTS.md`, root `validate*.ps1` | Only `DxUi` has a root `validate-specs.ps1` today; the validator set is a listed difference to converge. |
| `RedSalamander` | Never read, edit or index `Specs/Plans/WIP/Notes_Scratch.md` unless the user names that file. | `Specs/README.md` | The note is human-managed and outside specification authority. |
| `RedSalamander` | Never reuse an archived plan ID; the inventory rejects duplicate ranks. `Test-RSProtectedDoneHistory` protects completed-plan history. | `Specs/README.md`, `Tools/Modules/Tooling/SpecInformationArchitecture.psm1` (run through `Tools/Get-SpecInventory.ps1`) | The ranked WIP index and the protected-history check exist only there. |
| `RedSalamander` | No separate skill existed. Use `AGENTS.md`, `Specs/README.md` and the repository-local [tooling-governance](../../../../../RedSalamander/.github/skills/tooling-governance/SKILL.md) skill. Run `Tools/Get-SpecInventory.ps1 -FailOnFindings`. | `.github/skills/tooling-governance/SKILL.md` | `RedSalamander` keeps its skills under `.github/skills/`. |
| `RedXe` | For display, window, fullscreen, fallback or DPI work, the owner is [Specs/UI/UI_XeneonDisplayWindowing.md](../../../../../RedXe/Specs/UI/UI_XeneonDisplayWindowing.md). | `Specs/README.md` | The Xeneon display contract exists only in `RedXe`. |
| `RedXe` | Screenshots: `RedXe.exe --screenshot <png> --page <id> --widget <ordinal> [--after <ms>]` on a Debug build with a portable `--settings` scene (see `docs/usage.md`). Never use a mockup in place of a live capture. | `AGENTS.md`, `Common/WindowCapture.cpp` | The command and its flags belong to `RedXe.exe`. |
| `RedXe` | When a finished change impacts an end-user scenario, update `docs/` in the same closeout: global usage and/or the affected plugin page, including the screenshot when appearance or interaction changed. | `Specs/README.md`, `docs/plugins/` | The page-per-widget layout is specific to the `RedXe` plugin set. |
| `RedXe` | Run `.\validate-skills.ps1`, the repository-owned skill validation entrypoint, for specification-only or skill-only changes. Follow the [skill package contract](../../../../../RedXe/Specs/Build/Build_SkillPackages.md) for its structural and local-reference checks and their limits. Code changes still require the build and runtime checks owned by their domain spec; ordinary iteration uses affected coverage, with PrePush/Full accounting for qualification. | `Specs/Build/Build_SkillPackages.md` | The validation entrypoint and its test modes are `RedXe` tooling. |
| `RedPrism` | Domain specs and independent numeric golden cases own behavior. | `AGENTS.md`, `Specs/README.md` | Numeric goldens exist only in `RedPrism`. |
| `RedPrism` | Run `.\validate-skills.ps1` for skill or policy edits, plus the validation required by the owning spec. | `AGENTS.md` | The skill validator is invoked from the repository root. |
| `RedTilde` | Read [spec authority](../../../../../RedTilde/Specs/README.md) first. Keep unresolved language compatibility, native platform, physical input and release gates active. | `Specs/README.md`, `capabilities.json` | These gates belong to the `RedTilde` editor product. |
| `RedTilde` | `validate.ps1` checks links and indexes, skill metadata, lock and build inventory. Record one `Changes` fragment. | `AGENTS.md`, `validate.ps1` | `RedTilde` has one aggregate validator and no separate spec or skill scripts. |
| `RedMonitor` | Keep intended behavior in domain contracts and one canonical indexed WIP plan. Move a plan to Done only when all claimed scope is closed. | `Specs/README.md` | `RedMonitor` is a producer: its plan separates implementation from consumer, platform, interactive and performance gates. |

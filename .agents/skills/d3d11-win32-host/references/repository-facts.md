# Repository Facts

Product-specific facts for the shared [d3d11-win32-host](../SKILL.md) rules. Each row exists in one product only. The `DxUi` rows describe the `ControlHost` that `RedTilde` (`DxUi` API 5) and `RedMonitor`'s toolbar and status bar (API 4) present through, read at the commit `RedTilde` locks. The repository's `AGENTS.md` and `Specs/` win on any conflict. Rule differences between products are listed under [Differences To Converge](../SKILL.md#differences-to-converge).

| `RedMonitor` | The Direct3D host is the log view `ColorTextView`, a `WS_CHILD` window with its own scroll bars, an I-beam cursor and no class background brush. It owns one Direct3D 11 device, a 2-buffer `DXGI_SWAP_EFFECT_FLIP_SEQUENTIAL` swap chain with `DXGI_SCALING_NONE` and `DXGI_ALPHA_MODE_IGNORE`, and a Direct2D device context over the back buffer, and draws only with Direct2D and DirectWrite. The top-level window is not a Direct3D host: its class keeps `CS_HREDRAW \| CS_VREDRAW` and its `WM_PAINT` only validates. | [ColorTextView.cpp](../../../../../RedMonitor/src/ColorTextView.cpp) (`RegisterWndClass`, `Create`, `CreateDeviceResources`), [RedMonitor.cpp](../../../../../RedMonitor/src/RedMonitor.cpp) (`OnPaintMainWindow`) | The log view exists only in `RedMonitor`. |
| `RedMonitor` | `OnPaint` validates with `wil::BeginPaint`, then renders. `OnSize` records only the DIP client size; the buffers are resized in `OnPaint` (`EnsureBackbufferMatchesClient`), which resets the presentation state so the next present is a full frame. A scroll presents with `Present1`, one dirty rectangle and a scroll rectangle and offset. The sync interval is `0` between `WM_ENTERSIZEMOVE` and `WM_EXITSIZEMOVE` and `1` otherwise. No fallback or full-document layout is built during `WM_PAINT` in auto-scroll mode. | [ColorTextView.cpp](../../../../../RedMonitor/src/ColorTextView.cpp) (`OnPaint`, `OnSize`, `EnsureBackbufferMatchesClient`); [Core_Architecture.md](../../../../../RedMonitor/Specs/Core/Core_Architecture.md); the presentation state machine is planned in [ExplicitStateMachines_2026-11-10.md](../../../../../RedMonitor/Specs/Plans/WIP/ExplicitStateMachines_2026-11-10.md) (`PresentPlan`) | Scrolled presentation of a live log tail exists only in `RedMonitor`. |
| `RedMonitor` | Device loss reported by `EndDraw` or `Present1` calls `DiscardDeviceResources` (Direct2D first, then `ClearState` and `Flush` on the immediate context) and `ResetPresentationState`, requests a full redraw and invalidates. `RecreateSwapChain` flushes the context and releases the old swap chain before `CreateSwapChainForHwnd`. | [ColorTextView.cpp](../../../../../RedMonitor/src/ColorTextView.cpp) (`DiscardDeviceResources`, `RecreateSwapChain`) | The helper names are `RedMonitor`'s; the result set is under [Differences To Converge](../SKILL.md#differences-to-converge). |
| `RedMonitor` | The toolbar and status bar are `DxUi::WindowHost` children (`g_toolbarDxHost`, `g_statusDxHost`) at the `DxUi` API 4 commit in `Dependencies/DxUi.lock.json`. `DxHostWndProcThunk` attaches the host in `WM_NCCREATE`, forwards every message to `HandleMessage`, and clears `GWLP_USERDATA` in `WM_NCDESTROY`. The main window forwards `WM_DPICHANGED` to both. | [RedMonitor.cpp](../../../../../RedMonitor/src/RedMonitor.cpp) (`DxHostWndProcThunk`, `RegisterDxHostClass`, `OnDpiChangedMainWindow`) | The chrome layout is `RedMonitor`'s. |
| `RedMonitor` | `--warp` selects software rendering for ColorTextView and the DxUi toolbar and status bar. `--chrome-selftest` shows the main window without activating it (`SW_SHOWNOACTIVATE`, `WS_EX_NOACTIVATE` kept). `--monitor-scrollback-selftest` and the `MonitorTest.exe` self-tests that `test.ps1` lists are the other entry points. | [RedMonitor.cpp](../../../../../RedMonitor/src/RedMonitor.cpp), [UI_Viewer.md](../../../../../RedMonitor/Specs/UI/UI_Viewer.md), [Testing_Validation.md](../../../../../RedMonitor/Specs/Testing/Testing_Validation.md) | The common WARP switch has landed in all four Direct3D applications. |
| `RedTilde` | `RedTilde` owns the top-level window (class `RedTilde.MainWindow`, `WS_OVERLAPPEDWINDOW`, `WS_EX_NOACTIVATE` when headless) and attaches one `DxUi::ControlHost` to it with `forceWarp` from `--warp` and `batchInitialRootChildren`. `Application::WindowProc` binds the `Application` in `WM_NCCREATE`, forwards each message to `ControlHost::HandleMessage`, calls `DefWindowProcW` for what the host leaves, and in `WM_NCDESTROY` stops its workers, detaches the host and clears `GWLP_USERDATA`. `DxUi` owns the device, swap chain, `WM_PAINT`, `WM_ERASEBKGND` and device loss, and handles `WM_SIZE` and `WM_DPICHANGED` before `RedTilde` lays out its controls. | [Application.cpp](../../../../../RedTilde/RedTilde/Application.cpp) (`Initialize`, `WindowProc`), [Main.cpp](../../../../../RedTilde/RedTilde/Main.cpp); [Core_Architecture.md](../../../../../RedTilde/Specs/Core/Core_Architecture.md) | `RedTilde` is the only application whose main window is a `ControlHost`. |
| `RedTilde` | The caption is drawn by `DxUi` controls in the client area: the window extends the DWM frame by one pixel, and `WM_NCCALCSIZE` and `WM_NCHITTEST` (`FrameHitTest`) are `RedTilde`'s. Window placement (normal bounds, DPI, maximized) is restored through `ClampWindowBounds`, rescaled from the saved DPI and clamped to the monitor's work area in screen coordinates, and recorded at `WM_EXITSIZEMOVE` and `WM_DPICHANGED`. | [Application.cpp](../../../../../RedTilde/RedTilde/Application.cpp) (`Initialize`, `ClampWindowBounds`, `RecordWindowPlacement`) | Caption and placement are `RedTilde` product behavior. |
| `RedTilde` | `--capture`, `--benchmark`, `--performance-probe`, `--resource-probe` and `--self-test` create the window headless: never shown or activated. Hidden hosts get no invalidation-driven `WM_PAINT`, so `Application::Prepare` drains a bounded number of turns with `MsgWaitForMultipleObjectsEx`, and `Capture` reads the completed frame through `ControlHost::DebugCaptureBitmap(bitmap, true)`, which stages it before `Present`. | [Main.cpp](../../../../../RedTilde/RedTilde/Main.cpp), [Application.cpp](../../../../../RedTilde/RedTilde/Application.cpp) (`Prepare`, `Capture`) | Switch names stay repository facts until register E-13. |
| `RedTilde` | Printing renders on its own WARP device (`D3D_DRIVER_TYPE_WARP`, `D3D11_CREATE_DEVICE_BGRA_SUPPORT`) wrapped in `DxUi::GraphicsDevice`, never on the window's device. | [Printing.cpp](../../../../../RedTilde/RedTilde/Printing.cpp) | Printing exists only in `RedTilde`. |
| `DxUi` (for `RedTilde` and `RedMonitor`) | `ControlHost`, also named `WindowHost`, shares one Direct3D 11 device, DXGI factory and Direct2D device per owner thread, created through `CreateD3D11DeviceWithWarpFallback` (hardware, then WARP; a retry without the debug layer when that optional component is missing). `AttachOptions::forceWarp` selects WARP before the pool is in use, and a conflicting request fails with `ERROR_INVALID_STATE`. | [DxUi.WindowHost.cpp](../../../../../DxUi/src/Controls/DxUi.WindowHost.cpp) (`EnsureSharedWindowHostGraphicsResources`); [Rendering_Win32Host.md](../../../../../DxUi/Specs/Rendering/Rendering_Win32Host.md) | The shared pool is `DxUi`'s producer design. |
| `DxUi` (for `RedTilde` and `RedMonitor`) | Each attachment presents through a 2-buffer `DXGI_SWAP_EFFECT_FLIP_SEQUENTIAL` swap chain, for the HWND (`PresentationMode::HwndSwapChain`) or through DirectComposition with premultiplied alpha (`CompositionSwapChain`). `WM_PAINT` renders `rcPaint` inside `wil::BeginPaint` and presents a partial frame with `Present1` and one dirty rectangle; the first present after a buffer reset is full. `IsDeviceLossHResult` results discard the size-dependent and device resources and the shared pool, then invalidate. `SetNativePresentationVisible(false)` suppresses invalidation, preparation and rendering until restored. | [DxUi.WindowHost.cpp](../../../../../DxUi/src/Controls/DxUi.WindowHost.cpp); [Rendering_Win32Host.md](../../../../../DxUi/Specs/Rendering/Rendering_Win32Host.md) | `DxUi` owns this behavior once for every consumer; a consumer never reimplements it. |

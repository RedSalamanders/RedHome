# Repository Facts

Product-specific facts for the shared [d3d11-win32-host](../SKILL.md) rules. Each row exists in one product only. The repository's `AGENTS.md` and `Specs/` win on any conflict. Rule differences between products are listed under [Differences To Converge](../SKILL.md#differences-to-converge).

| Repository | Fact | Where it is defined | Kept because |
| --- | --- | --- | --- |
| `RedPrism` | Frame order in `Renderer::Render`: clear → chrome `Prepare` (layout decides the canvas hole) → composition `Compose` (only when the document changed) + `BlitToTarget` → chrome `Composite` over the canvas → one `Present`. | `RedPrism/Renderer.cpp`; contracts in [UI_ApplicationChrome.md](../../../../../RedPrism/Specs/UI/UI_ApplicationChrome.md) and [Rendering_Composition.md](../../../../../RedPrism/Specs/Rendering/Rendering_Composition.md) | Document canvas plus DxUi chrome exist only in `RedPrism`. |
| `RedPrism` | Rebind the back-buffer RTV after the composition pass; it unbinds its targets. | [Rendering_Composition.md](../../../../../RedPrism/Specs/Rendering/Rendering_Composition.md) | Composition pass exists only in `RedPrism`. |
| `RedPrism` | Textures cached by a CPU identity (`Raster::Identity()`) hold the owning `Raster` and are swept after each composition. | [hlsl-composition](../../../../../RedPrism/.agents/skills/hlsl-composition/SKILL.md), [Rendering_Composition.md](../../../../../RedPrism/Specs/Rendering/Rendering_Composition.md) | `Raster` is a `RedPrism` type. |
| `RedPrism` | Create the device with `D3D11_CREATE_DEVICE_BGRA_SUPPORT` so DxUi can borrow it from C2. | `RedPrism/Renderer.cpp`; integration contract in [Core_DxUiIntegration.md](../../../../../RedPrism/Specs/Core/Core_DxUiIntegration.md) | The C2 borrow path is `RedPrism`'s DxUi integration. |
| `RedPrism` | The titled window is DPI-adjusted to a 1280×800 logical client canvas; hidden `--self-test` asserts it. | [UI_Windowing.md](../../../../../RedPrism/Specs/UI/UI_Windowing.md) | Canvas size is a `RedPrism` product value. |
| `RedXe` | Startup window mode, display selection, Debug and Release window modes (titled `WS_OVERLAPPEDWINDOW` at a 2560×720 logical client canvas on the XENEON EDGE, borderless fullscreen popup that uses the suggested monitor rectangle at `WM_DPICHANGED`) and the screen-edge dock window kind. | [UI_XeneonDisplayWindowing.md](../../../../../RedXe/Specs/UI/UI_XeneonDisplayWindowing.md) | XENEON EDGE hardware and dock mode exist only in `RedXe`. |
| `RedXe` | UI-thread `OleInitialize`, the top-level `IDropTarget`, and forwarding pointer and drop input to GPU widgets. | [Plugins_API.md](../../../../../RedXe/Specs/Plugins/Plugins_API.md), [UI_Dashboard.md](../../../../../RedXe/Specs/UI/UI_Dashboard.md) | Dashboard widgets exist only in `RedXe`. |
| `RedXe` | Keep host graphics ownership inside `RedXe/Renderer.*`; plugin-specific shaders, geometry and buffers stay inside their plugin projects. Compile bundled-plugin HLSL at build time and embed the bytecode. | [Plugins_API.md](../../../../../RedXe/Specs/Plugins/Plugins_API.md) | The plugin model exists only in `RedXe`. |
| `RedXe` | Launcher icon textures and the 3D launch animation are owned by `Plugins_API.md`. | [Plugins_API.md](../../../../../RedXe/Specs/Plugins/Plugins_API.md) | Launcher exists only in `RedXe`. |
| `RedXe` | Notify GPU widgets after device creation and before device release. Rebind the host target and widget viewport before every plugin render callback. Page-swipe viewports keep each tile's full size and may sit partly off the render target; invoke `Render` for every positive-size viewport on the current and staged pages and do not shrink the rectangle to the visible slice. | [UI_Dashboard.md](../../../../../RedXe/Specs/UI/UI_Dashboard.md), [Plugins_API.md](../../../../../RedXe/Specs/Plugins/Plugins_API.md) | GPU widgets and page swipe exist only in `RedXe`. |
| `RedXe` | Host placeholder tiles fill with `ClearView`; that API is not on `ID3D11DeviceContext`, so query `ID3D11DeviceContext1`. | [UI_Dashboard.md](../../../../../RedXe/Specs/UI/UI_Dashboard.md) | Placeholder tiles exist only in `RedXe`. |
| `RedXe` | Host chrome (edge bands, raise dim/shadow/close) is `RedXe/HostChrome.*`: one quad pipeline, one 64-byte constant buffer, one `R8` glyph atlas rasterized with DirectWrite per DPI. Draw dim strips and shadow before the raised widget and the close control and bands after it; never create a chrome HWND or GDI object. Add glyphs through `FluentIcons.h` and the `HostChromeGlyph` slots. | [UI_Dashboard.md](../../../../../RedXe/Specs/UI/UI_Dashboard.md), [HostChrome.h](../../../../../RedXe/RedXe/HostChrome.h), [FluentIcons.h](../../../../../RedXe/RedXe/FluentIcons.h) | Host chrome pipeline exists only in `RedXe`. |
| `RedXe` | Log one `device-created` record per device creation. | [Renderer.cpp](../../../../../RedXe/RedXe/Renderer.cpp) | Logging contract is `RedXe`'s. |
